# Open Island Security Audit — 2026-05-03 (P0)

**Scope:** Threat model B — *agent CLI compromis*. An attacker controls
the JSON payload an agent (Claude Code, Codex, OpenCode...) sends to
the OpenIsland hook bridge. The user trusts OpenIsland's UI to surface
what the agent is about to do; if that UI can be manipulated the
attacker can social-engineer approvals.

This audit focuses on the inline-diff feature added on
`feat/inline-diff-and-plan-mode` and a quick read of the bridge surface.

**Branches reviewed:** `feat/inline-diff-and-plan-mode` HEAD `6ecacd3`.

---

## Findings

### F1 — File-path display truncation hides traversal targets [HIGH]

**Location:** `Sources/OpenIslandApp/Views/InlineDiffView.swift:130-137`
(`displayName(for:)`)

**Issue:** The approval card shows only the last two path components
(`parent/file.ext`). An agent can craft a `file_path` whose tail looks
innocuous while the full path points somewhere sensitive:

```
file_path: "/Users/victim/.cache/safe-folder/launchd.plist"
displayed: "safe-folder/launchd.plist"
```

The user clicks Yes thinking they're approving a write under a
`.cache/...` path; the actual write goes wherever the agent specified.
The middle truncation in the `Text` modifier doesn't help because the
view is given a tail-truncated string in the first place.

**Reproduction:**
```swift
let diff = ToolDiff(filePath: "/etc/launchd.plist",
                    lines: [.add("benign")],
                    additionCount: 1, removalCount: 0)
// displayName(for: diff.filePath) → "/etc/launchd.plist" → "etc/launchd.plist"
// Mostly fine, but for paths > 2 components a critical absolute path
// can be hidden: "/Users/victim/Documents/safe/.ssh/authorized_keys"
// → ".ssh/authorized_keys"
```

**Mitigation:**
- Show the full absolute path with middle truncation by AppKit
  (`Text(filePath).lineLimit(1).truncationMode(.middle)` on the raw
  path), so a deeply nested path collapses with `/Users/.../authorized_keys`
  rather than dropping the prefix entirely.
- Add a visual warning when the path is outside the user's home or the
  workspace cwd: red badge + "writes outside workspace" caption.

### F2 — Unicode bidi override / Trojan Source attack [HIGH]

**Location:** `Sources/OpenIslandApp/Views/InlineDiffView.swift:94`,
`Sources/OpenIslandApp/Views/LightweightSyntaxHighlighter.swift:25-32`

**Issue:** Diff lines are rendered as `AttributedString` directly via
`Text`. SwiftUI honors Unicode bidi controls (U+202E `RIGHT-TO-LEFT
OVERRIDE`, U+2066 `LRI`, U+2067 `RLI`). An attacker can construct a
diff line that *displays* as one thing but executes another — the
classic "Trojan Source" attack
([Boucher & Anderson 2021](https://trojansource.codes/)).

Same applies to `apply_patch` parsing
(`Sources/OpenIslandCore/ToolDiffExtractor.swift:103-121`) — raw line
text is passed through unchanged.

**Reproduction:**
```swift
// Add line that visually reads "if user.isAdmin { grantAccess() }"
// but actually runs grantAccess unconditionally.
let payload = "if user.isAdmin { \u{202E}/* tnemhsidnA */ \u{2066}grantAccess() }"
```

**Mitigation:**
- Either: strip ALL bidi/format control chars before rendering (U+202A-U+202E,
  U+2066-U+2069, U+200B-U+200F, U+FEFF) and replace with a visible
  placeholder like `␣` to alert the user.
- Or: render lines with `text.environment(\.layoutDirection, .leftToRight)`
  AND use a font/representation that ignores embedded bidi (NSAttributedString
  with `NSWritingDirection` forced LTR).

The strip-and-flag approach is safer because it makes the attack
visible rather than just neutralizing it.

### F3 — Zero-width characters hide identifier substitutions [MEDIUM]

**Location:** Same as F2.

**Issue:** Zero-width chars (U+200B ZWSP, U+200C ZWNJ, U+200D ZWJ) are
invisible. An attacker can substitute identifiers:

```
- function login(user, password) { authenticate(user, password) }
+ function login(user, password) { authentic​ate(user, password) }
```

The diff displays as a no-op but `authentic​ate` is a different
identifier from `authenticate`. If the file has a malicious
`function authentic​ate(...) { exfil(...) }` defined elsewhere, the
swap silently re-routes execution.

**Mitigation:**
- Same as F2 (strip + flag) covers this.
- A weaker mitigation: highlight any line containing non-ASCII chars
  with a "contains hidden characters" badge.

### F4 — apply_patch +++ filename spoofing [MEDIUM]

**Location:** `Sources/OpenIslandCore/ToolDiffExtractor.swift:101-123`

**Issue:** The parser captures only the LAST `+++ b/<path>` line as
the displayed `filePath`. Multi-file patches lose their first N
filenames. Worse, an attacker can construct:

```
+++ b/safe-display-name.swift
@@ -1 +1 @@
-x
+y
+++ b/dangerous-target.swift
```

The displayed filename will be `dangerous-target.swift` (last wins) —
but the agent can also flip it: place dangerous-first and safe-last
so the diff displays a "safe" filename while the patch hunks earlier
in the body modify the dangerous file.

**Mitigation:**
- Reject patches with multiple `+++` headers (treat as malformed).
- Or: render each `+++` segment as its own `ToolDiff` with its own
  filename header, so the user sees every target file.

### F5 — Bridge Unix socket has no peer authentication [MEDIUM]

**Location:** `Sources/OpenIslandCore/BridgeServer.swift:107-141`,
`Sources/OpenIslandCore/BridgeTransport.swift:13-19`

**Issue:** The default socket is at
`~/Library/Application Support/OpenIsland/bridge.sock`. The server
never calls `chmod` on the file nor checks the connecting peer's uid
(`getpeereid` on macOS). The macOS default umask `022` means the
socket file is created mode `0644`, which prevents non-owner connects
on a multi-user system, BUT:

1. **Same-user processes** (any other tool the user runs) can connect
   freely. A malicious tool with user-level execution can spoof
   PreToolUse events and trick the user into approving fake actions
   that look like they come from Claude/Codex.
2. **Legacy socket at `/tmp/open-island-<uid>.sock`** — `/tmp` is
   shared. The legacy listener still runs (`BridgeServer.swift:101`)
   for backward compat. Same-user processes can connect; cross-user
   connects depend on file mode (likely 0644 again, so OK there).

**Reproduction:**
```bash
# As the same user as OpenIslandApp, with Python / nc:
echo '{"type":"permissionRequested","sessionID":"x","request":{"title":"Allow Bash","summary":"...","affectedPath":"rm -rf ~"}}' | \
  nc -U "$HOME/Library/Application Support/OpenIsland/bridge.sock"
```
The notch displays a fake approval card.

**Mitigation:**
- After `bind()`, `chmod(socketPath, 0600)` so even other-user processes
  can't connect.
- Add `getpeereid()` check in the accept loop; reject non-owner peers
  even on the legacy `/tmp` path.
- Drop the legacy `/tmp` listener once enough time has passed since the
  installer started writing the new path.

### F6 — TerminalTextSender escape: newlines pass through [LOW]

**Location:** `Sources/OpenIslandApp/TerminalTextSender.swift:282-287`
(`escapeAppleScript`)

**Issue:** The escape replaces `\\` and `"` but leaves literal newlines
(`\n`, `\r`) in the text. Embedded in:

```applescript
keystroke "first\nsecond"
```

AppleScript accepts multi-line string literals, so this works; the
keystroke command just types the multi-line text. Not directly an
injection vector — but a reply containing a newline behaves
non-obviously and could surprise a user.

**Note:** This is *user-initiated* text injection (the user types the
reply themselves), so it's not part of threat model B. Logged here for
the broader audit.

**Mitigation:**
- Replace `\n`/`\r` with a single space, OR display a "multi-line reply
  not supported" hint when the user types one.
- Future: send each line as its own `keystroke + key code 36 (Enter)`
  pair so the agent receives the same multi-line text it would have if
  typed manually.

### F7 — Long lines, tab vs space, and visual padding manipulation [LOW]

**Location:** `Sources/OpenIslandApp/Views/InlineDiffView.swift:87-101`

**Issue:** A diff row uses `.fixedSize(horizontal: false, vertical: true)`
which lets text wrap vertically. A line with 4000+ chars wraps to dozens
of display rows, potentially pushing the actual change out of the 240px
viewport unless the user scrolls. Combined with whitespace abuse
(thousands of trailing spaces) the user might miss what's after the
visible portion.

Tabs are rendered at the system tab width. An attacker can mix tabs
and spaces to make two visually-aligned columns appear identical while
they're semantically different.

**Mitigation:**
- Cap displayed line length to e.g. 500 chars per line, with a "(truncated)"
  badge on the row.
- Render whitespace explicitly (tab → `→ `, trailing space → `·`) like
  GitHub's "show whitespace" diff option, so manipulation is visible.
